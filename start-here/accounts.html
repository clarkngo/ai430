GitHub

First needed: AIC 1Free — no credit card

What it's for: hosting your own repo for each AIC (build and Part B challenge), running it in GitHub Codespaces, a ready-made cloud dev environment, and from AIC 2 on, running your pipelines in GitHub Actions on the free minutes every account gets.

  1. Go to github.com and click Sign up (top right).
  2. Enter an email, create a password, and pick a username. Use something professional: this account is worth keeping for internships and job applications.
  3. Verify your email when GitHub sends the confirmation.
  4. That's it for a free account: no payment information is requested or required.
Already have a GitHub account from another course or your own projects? Use that one; don't create a second. If you're a student, the free GitHub Student Developer Pack raises your Codespaces hours, but the course doesn't require it.

You'll know it worked when…

  • You can sign in at github.com and see Code → Codespaces → Create codespace on main on any repository, and an Actions tab on your own repos.
🔑

Google AI Studio: Gemini API key

First needed: AIC 1Free — no credit card

What it's for: the API key that lets the support agent, the judge and the red-team runs talk to Gemini. You get it once, in AIC 1, and reuse the same key all term. Already have one from another course? Use that one.

  1. Go to aistudio.google.com/apikey and sign in with any Google account (a personal Gmail account is fine).
  2. Click Create API key.
  3. Copy the long string it gives you: it starts with something like AIza....
  4. Paste it into your project's .env file:
    GOOGLE_API_KEY=AIzaSyD-your-real-key-goes-right-here
  5. In AIC 2 you also add it as a repository secret named GOOGLE_API_KEY (Settings → Secrets and variables → Actions), so the evaluation gate can run in GitHub Actions.
Treat this like a password. Anyone with your key can use your quota. Never paste it into a file you commit, a chat message, an AI assistant or a screenshot. That's why it lives in .env and in repository secrets, never in your code or a workflow file.

You'll know it worked when…

  • You have a key starting with AIza pasted into .env as GOOGLE_API_KEY (not .env.example, which is just a template).

Hugging Face

First needed: AIC 2Free — no credit card

What it's for: a free Space on the free CPU hardware that hosts Salish Fresh's forecast form and support chat, and a write token that your deploy.yml workflow uses to push each release to it.

  1. Go to huggingface.co/join and sign up with an email; verify it.
  2. Create a Space: huggingface.co/new-space. Choose the Gradio SDK and the free CPU basic hardware. Name it, for example, salish-fresh.
  3. Create a token: Settings → Access Tokens → Create new token, type Write. Copy it: it starts with hf_.
  4. In your AIC 2 repo on GitHub, add it as a repository secret named HF_TOKEN, and add a repository variable HF_SPACE with your Space's name, such as your-name/salish-fresh.
Free hardware sleeps. A free Space pauses after a period with no visitors and takes a little while to wake on the next visit. That's normal; it isn't a failed deploy. Don't upgrade the hardware: anything that asks for billing is out of scope.

You'll know it worked when…

  • Your Space's page loads (even as an empty "building" Space), and HF_TOKEN and HF_SPACE appear in your repo's Actions settings.

Langfuse

First needed: AIC 3Free — no credit card

What it's for: tracing: a record of what the agent actually did on every request (each model call, retrieval and tool call, with inputs, outputs and timings), plus the judge's score attached to each trace. AIC 3 is built around it, and your Term Project uses it too.

  1. Go to cloud.langfuse.com and sign up on the free Hobby plan.
  2. Create a new project (any name, such as ai430).
  3. Go to Settings → API Keys and create a key pair: a Public Key (pk-lf-...) and a Secret Key (sk-lf-...).
  4. Add all three to the .env in your AIC 3 repo. Use your project's region: https://cloud.langfuse.com for EU, or https://us.cloud.langfuse.com for US.
    LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_HOST=https://cloud.langfuse.com
Two keys, not one. Langfuse needs both the public and the secret key. If either is missing, traces fail silently or the run errors at startup, so check both made it into .env.

You'll know it worked when…

  • Your Langfuse project's Traces tab shows entries after you run python -m evals.run_week in AIC 3. Traces can take a few seconds to appear.

Putting it all together

Each AIC repo has its own .env, copied from .env.example, and AIC 2 onwards also has repository secrets for GitHub Actions. You add each one when an AIC first needs it:

# .env · AIC 1
GOOGLE_API_KEY=AIzaSyD-your-real-key-goes-right-here
MLFLOW_TRACKING_URI=http://127.0.0.1:5000

# .env · AIC 3
LANGFUSE_PUBLIC_KEY=pk-lf-...
LANGFUSE_SECRET_KEY=sk-lf-...
LANGFUSE_HOST=https://cloud.langfuse.com

# Repository secrets and variables (GitHub → Settings → Secrets and variables → Actions) · AIC 2
HF_TOKEN=hf_... (secret)
GOOGLE_API_KEY=AIza... (secret)
HF_SPACE=your-name/salish-fresh (variable)

.env is excluded from Git by each repo's .gitignore: it stays in your Codespace, never committed. Secrets never go in a workflow file.
