What this teaches

  • The data is part of the model. Same code, different batch, different MAE. Without the data version in each run, you can't say which batch made a model worse.
  • A renamed column doesn't crash anything. With validation off, the missing temperature is filled in and training succeeds: the model is just quietly worse.
  • Stop it at the door. A schema check costs a second; a bad model in production costs a week of wrong forecasts.
  • Types aren't enough. The stuck-sensor batch passes the starter schema. Only a rule about the values (one unique temperature all week) catches it.
  • Newest ≠ production. Promote and roll back move an alias; the runs themselves never change.
