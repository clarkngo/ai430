AIC 3: Observability, Evaluation & RAG Performance

Instrument everything Salish Fresh runs: a drift report for the demand model, a Langfuse trace with a judge score and per-step latency for every agent answer, and a retrieval benchmark across Chroma and Qdrant. Then check whether each signal would actually warn you.

Before you start

  1. Check your account setup. This AIC needs a free Langfuse account and its two keys, plus the GitHub account and Gemini key from AIC 1. Set them up first; the build won't run without them.
  2. Know the concepts. Read Concept Companion → Module 3 before you open the starter code.

What you'll need

  • Starter code: your AIC 3 repo, created from the AI430-AIC03 template when you accept the AIC 3 invite (Planned planned (the Classroom50 link is added here once the AI430-AIC03 template repo is built and tested)). Open it in GitHub Codespaces; dependencies install automatically. Not sure what a file does? See the starter code walkthrough for this AIC.
  • Your Langfuse public key, secret key and host in .env.
  • Docker in the Codespace (the devcontainer includes it) for Qdrant: docker compose up -d qdrant.
  • An AI coding assistant in your Codespace (Copilot Chat in Agent mode, or equivalent)

Reference reading (optional, before you start)

  • Evidently documentation — the data drift preset.
  • Langfuse documentation — tracing and scores.
  • Ragas documentation — context precision and recall.
  • Chroma and Qdrant quickstarts.

This guide covers the build: Part A (Create / Scaffold, Evaluate) and the first half of Part B (Analyze, Understand & Refine). It is graded across those stages instead of on code correctness alone, for 60 of the 100 AIC points: 12 points each for Create, Evaluate, Analyze, Apply (the change you make by hand in Understand & Refine) and Understand (your own explanation of it, plus the short Post Mortem you write after the challenge). The other 40 points are the Part B challenge, in the challenge/ folder of the same repo. The whole AIC is graded once, at the end of Week 6. Each stage below says exactly what to submit. Everything goes in your Module 3 GitHub Classroom repo: written work under the matching heading in NOTES.md, screenshots in screenshots/. Commit and push as you go. By the end of Week 6, push your final work: your repo is your submission, so there is nothing to submit in Brightspace, and your last push before the deadline is what counts.

1 · Create / Scaffold

Graded under Build: Create, 12 of the 100 AIC points. The AI-assisted starting point, not the deliverable.

The starter has pantry_helper with its help-centre index built in both databases (rag/build_index.py), a recorded week of 40 customer questions (evals/week.json), a judge rubric (evals/rubric.md), 30 retrieval questions with known good passages (bench/questions.json) and weekly order batches for the drift report. Do the three pieces in order. First, tracing and the judge, with this prompt:

In THIS existing workspace (the starter-code folder that's already open),
edit files here; do not create a new workspace or project.
Instrument pantry_helper for Langfuse:
- In observability/tracing.py, set up Langfuse's OpenTelemetry
  integration for Google ADK so every run of pantry_helper is a trace
  with one span per model call and tool call. Keys come from .env.
- In evals/judge.py, write judge(question, trace) -> dict that asks
  JUDGE_MODEL to grade the run against evals/rubric.md and returns
  {"score": 0 or 1, "reason": str} as JSON. Attach the score to the
  trace in Langfuse as "reasoning_accuracy".
- In evals/run_week.py, run each question, judge it, and write
  results/week.csv with question id, score, total seconds, and seconds
  per span name.
MODEL and JUDGE_MODEL stay "gemini-3.8-flash". Don't change the
agent's prompt or tools.
python -m evals.run_week --questions evals/week.json --pause 4

Second, the drift report. Prompt your assistant to write monitoring/drift_report.py: an Evidently data-drift report comparing a batch with the training data, saved as HTML in reports/, plus a JSON summary of which features drifted. Third, the benchmark: bench/retrieval.py, which runs the 30 questions against Chroma and Qdrant at top-k 3, 5 and 10 and writes context precision, context recall, retrieval ms and prompt tokens per setting to results/bench.csv. Keep the prompts you used.

Submit
  • The prompts you gave your AI assistant, and screenshots of one trace in Langfuse (with its score), the drift report, and the benchmark table.
🔍

2 · Evaluate

The critical gate — is the AI-produced result actually correct?

Test every signal on a case where you know the right answer:

  • Inject drift. Run the report on data/batches/week-09-sensor.csv, where one feature is shifted on purpose. Does it flag that feature, and only that one?
  • Check the judge. Grade 10 traces yourself with evals/rubric.md before looking at the judge's scores. Then compare: agreement out of 10, and what each disagreement was about.
  • Find the slow span. From results/week.csv, compute p50 and p95 for the whole run and per span name. Which step drives p95?
  • Benchmark retrieval. For both databases at top-k 3 and 10: context precision, recall, retrieval ms and prompt tokens. Which change cost the most, and in what?
Submit
  • Your agreement table, the p50/p95 table and the benchmark output, and a short note: what each signal caught, and the retrieval trade-off in one sentence.
🔬

3 · Analyze

Why does this work, mechanically?

Pick one of these and explain it in your own words:

  • How the drift report decides. Pick one feature: which two distributions does Evidently compare, with what statistic, and against what threshold? Why is the training data the reference?
  • The judge and its agreement. Walk through evals/judge.py: what the judge sees and returns. Explain your agreement number and one disagreement in detail.
  • The retrieval trade-off. From your benchmark, explain why precision and recall moved in opposite directions as top-k rose, and use your spans to show where the extra latency came from.
Submit
  • A written walkthrough of the one you chose (250–400 words), quoting the lines, log lines or trace steps you're explaining.
✋

4 · Understand & Refine

The mastery check — by hand, no AI assistance for this stage.

By hand this time — no AI assistance for this stage.

Write the one alert you'd want to be woken for, by hand, in monitoring/alerts.py:

  • Pick the signal: drift on a key feature, the judge score's 3-day trend, or p95 latency.
  • Write the rule and its threshold, and justify the threshold with a number from your Evaluate results.
  • Show it firing on results/degraded-week.csv, with a message that says what to look at first.
  • Show it staying quiet on the normal week. Add both as tests in tests/test_alerts.py.
Submit
  • Your rule in alerts.py and its two tests (Apply).
  • Your own explanation under Understand & Refine in NOTES.md: why this signal and this threshold, who should receive the alert, and what it would miss (Understand).

Common snags

  • No traces appear in Langfuse — check that both keys are set and that LANGFUSE_HOST matches your project's region (https://cloud.langfuse.com for EU, https://us.cloud.langfuse.com for US). Traces can also take a few seconds to show up.
  • Every span has the same duration — the spans are being created after the work, not around it. Check that tracing is set up before the agent runs, in observability/tracing.py.
  • Qdrant: connection refused — docker compose ps shows whether it's running; docker compose logs qdrant shows why not.
  • Ragas asks for an OpenAI key — by default it uses OpenAI. The starter's bench/ragas_setup.py points it at Gemini instead; import it before running any metric, and never add a paid key.
  • The drift report flags every feature — you compared against the wrong reference (for example, an empty or tiny frame). The reference is the training data from AIC 1.
  • 502 Bad Gateway, a 404 or "model not found" from the agent — almost always the model name. AI assistants default to whatever model was current in their training data, such as gemini-2.5-flash, which new API keys can't use. Set it back to gemini-3.8-flash. If that ever stops working, check the current list at ai.google.dev/gemini-api/docs/models.
  • 429 RESOURCE_EXHAUSTED — you hit the free Gemini tier's per-minute limit. Wait a minute and rerun; the starter scripts' --pause option adds a gap between calls.

Most snags trace back to a concept. If one doesn't make sense, see Concept Companion → Module 3.
